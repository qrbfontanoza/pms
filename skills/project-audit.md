# Project Audit

## Purpose

Completely understand the project before making any modifications.

## Responsibilities

Always inspect the relevant source code before answering.

Never assume architecture or implementation details.

Search the entire project whenever necessary.

Explain how the current implementation works before recommending improvements.

Identify dependencies between files.

Generate documentation instead of modifying code whenever possible.

## Rules

- Never guess.
- Never redesign immediately.
- Preserve existing functionality.
- Cite exact files used as evidence.
- Clearly distinguish verified facts from assumptions.

## Output

Produce:

- Technology stack
- Folder structure
- Feature inventory
- Database overview
- Authentication flow
- Admin flow
- Customer flow
- UI structure
- Known issues
- Suggested improvements
